修复了单局胜利后进入选角会重置完成状态并重新接管的问题：模组一局结束即停止，下一局由明确启动的流程重启进程授权。关闭录屏后仍独立生成 run ID，不把跨波次误判为新一局；每局清空治疗与集火统计。

Boss 设计依据本机 1.2.0.1 原生实现：

1. 先补附属弹体覆盖：追猎者旋转弹在 Boss/Pivot 下，现有扫描仅遍历主场景独立弹体容器，漏掉附属旋转弹；预测要包含父节点平移、角速度和径向展开，不能套普通直线弹模型。真实命中记录中已出现 Boss/Pivot 弹体。
2. 冲刺预警用当前攻击行为的冷却、蓄力动画进度和锁定方向。追猎者初始配置冷却 120 tick、蓄力动画长度 0.4 / 播放速率 0.5、冲刺 0.5 秒；动画完成会改变播放速率，转阶段也会换行为，不能固定按 2 秒循环。冷却将尽时不主动贴近；已锁方向后侧移离开冲刺走廊；冲刺结束后重新评估输出窗口。
3. 双 Boss 集火采用距离、剩余血量和当前危险阶段综合选择，并加入切换滞后。相近且安全时先收掉残血，减少同时存在的威胁；危险蓄力时暂停追击。追猎者危险优先级应结合当前接敌风险，不能规定任何距离下都追它；武器瞄准与走位共享选定目标。
4. 生命低、Boss 冲刺或旋转弹走廊威胁高时，避让和治疗先于近战输出；为冷却、阶段、预计冲刺时刻、集火对象及切换原因增加日志，再实战验证。上述是设计与待实现项，不计为已验证能力。

若当前 FFmpeg 的 NVENC 接口高于驱动支持版本，可设置 `BROTATO_NVENC_FFMPEG` 为兼容 FFmpeg 可执行文件路径。脚本也会检查本机 `tools/ffmpeg-compatible/ffmpeg-8.0-full_build/bin/ffmpeg.exe`。此时由新版 FFmpeg 按 PID/HWND 捕获窗口，经管道交给兼容版本使用 NVENC 编码。兼容程序需自行准备，当前已实测 FFmpeg 9 捕获配合 FFmpeg 8 编码。默认录制为 1920×1080、60 FPS、无声。

### 策略概览

#### 战斗与拾取

- 每次走位评估 24 个方向，结合敌人和弹幕的位置、速度预测短时间内的接触风险，同时考虑地图边界、目标距离和转向惯性。
- 重点分析周围 420 像素的威胁，远处普通敌人按网格聚合，近身敌人和 Boss 保留独立身体。长条斩击按实际形状、旋转及预警后的生效时窗计算风险。
- 每 0.25 秒更新材料与治疗物目标，权衡拾取价值、距离和接近路径的危险。血量不足时提高治疗物价值，低血且威胁密集时放弃追材料，没有合适目标时沿宽弧线绕行。

#### 配装与商店

- 以冲锋枪起步，目标组合为 4 把冲锋枪加 2 把双管霰弹枪，利用高频命中、穿透和击退。缺霰弹枪时允许临时用冲锋枪补槽，实际组合取决于商店供给。
- 前期优先补武器数量，满槽后按当前枪械的直接 DPS 增量评估升级和远程伤害收益。生命、护甲、攻速、吸血等按当前属性与波次动态评分，缺少的生存属性权重更高，后期降低收获等经济属性权重。
- 购买先检查价格、原生购买条件和最低收益，再按收益除以“价格加 15”排序。满槽需要腾位时，先确定要买的武器，再合并已有同阶武器并重新确认购买条件。
- 道具评分考虑穿透等配装协同及重复收益递减，并过滤会突破关键属性底线、强制低血开局、额外刷怪或持续自伤等当前策略难以承受的副作用。
- 刷新保留采购资金。第 8 波起最多刷新 16 次，刷新支出上限为入店资金的 35% 与 60 材料中的较大值，同时保留 `100 + 8 × 波数` 的购买预算。
